## Context

`c:\Users\Ali\Documents\print automater` contains exactly one file: the 130-section Master PRD. No code, no scaffolding, one commit (`4752959 first commit`) holding the spec.

The PRD describes a digital-to-physical printing platform: a customer uploads a PDF, configures it, picks a shop, pays; the shop verifies payment in an Expo app and approves; a Printer Agent on the shop's PC pulls the job and drives a real printer. Everything serves one requirement (§129):

> A customer pays for a correctly configured print job, an authorized shop approves it, and the correct physical document is printed reliably and securely.

This plan builds that loop in 4 weeks, for **one developer working with Claude Code**, with a real printer available from Phase 9.

**Stated concern, then moving on:** Phases 9–10 will need revision once the agent meets real hardware — Windows print-queue reporting is inconsistent across drivers. Everything is specified tightly enough to execute; expect that phase to absorb the surprises.

## 3. Architecture at a glance

**Two independent state machines** (§26 — payment status and print status must never be conflated):

- **Order** (§25): `DRAFT → UPLOADED → PAYMENT_PENDING → PAID → WAITING_FOR_SHOP → SHOP_ACCEPTED → QUEUED_FOR_PRINT → PRINTING → PRINTED → READY_FOR_COLLECTION → COMPLETED`, plus `PAYMENT_FAILED, SHOP_REJECTED, PRINT_FAILED, PRINT_STATUS_UNKNOWN, CANCELLED, EXPIRED`
- **Payment** (§24): `PENDING → AUTHORIZED → PAID`, plus `FAILED, CANCELLED, REFUND_PENDING, REFUNDED, REFUND_FAILED`

**Authorization is three stacked guards** on every protected route (§81): `JwtAuthGuard` → `RolesGuard` → `ShopScopeGuard`. Customer ownership is checked in the service layer.

**Documents never travel unencrypted or unaudited:** presigned upload to a quarantine prefix → worker validates and envelope-encrypts → authenticated streaming reads only. No permanent public URLs (§65).

**Schema** covers the PRD's 13 tables (§51) plus five the design requires: `refresh_tokens`, `idempotency_keys`, `order_number_counters`, `agent_pairing_codes`, `refunds`. Migrations are introduced per phase, not all at once.

## 17. Risks

| Risk                                           | Mitigation                                                                                                                                                         |
| ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **SumatraPDF is GPLv3**                        | Invoked as a separate process (aggregation, not linking), license shipped. PrinterDriver abstraction allows a swap. **Needs a decision before commercial launch.** |
| Windows print-queue reporting varies by driver | Queue job must vanish without error before PRINTED; show "Printing…" not fake progress                                                                             |
| 28 days solo is aggressive                     | Phases 11–12 are P1 and compressible; Phases 0–9 are not                                                                                                           |
| Mock payments hide real PSP quirks             | Mock fires real HMAC webhooks incl. replay/reorder; real provider = one adapter class                                                                              |
| Envelope encryption blocks direct-to-S3 reads  | Deliberate: all reads via authenticated, audited endpoints                                                                                                         |
| ClamAV adds latency/container everywhere       | Feature-flagged, can disable for pilot                                                                                                                             |

## 18. Commit discipline

**One commit per sub-phase, no exceptions, made only after its Done-when condition is verified.**

- Finish a sub-phase's Build → verify its Done-when condition → stage only the files that sub-phase touched → commit.
- Commit message: `<phase>.<sub> <short imperative summary>`.
- Never bundle two sub-phases into one commit.
- Never commit a sub-phase that fails its own Done-when condition.
- Phase-level commits get an additional milestone marker on top of the last sub-phase's commit.
- Follow the attribution footer given in the system reminder for every commit.
